# 术语表

- 经营快照：每日既有批处理生成的 PMS、OTA 和经营建议汇总，不是交互查询入口。
- 价格摘要：最多 5 条自家与同类竞品的重点 OTA 价格对比。
- 规则建议：Hermes 不可用时，根据真实入住率、库存和价格摘要生成的确定性建议。
- Hermes 分析：仅接收筛选后的结构化经营数据、无本地读写工具的一次性综合分析。
- `occupancy-watch`：独立的 45 分钟 PMS 库存差分监控，不属于经营快照批处理。
- 自有酒店：需要独立采集 PMS、OTA、生成决策并推送的经营主体，以 `own_hotel_key` 唯一标识。
- 竞品绑定：某家自有酒店可参与比价的启用竞品集合，不是全局竞品列表。
- 酒店集合：一家自有酒店及其绑定竞品组成的一次抓价和决策边界。
- 推送路由：自有酒店到 webhook 环境变量名的映射；数据库不保存真实 webhook。
- 事实仓库：TimescaleDB 中可追溯的 PMS、OTA、展会、调价决策和运行事实，是经营判断的数据源。
- 记忆候选：从旧记忆或事实仓库筛选出的长期规则与典型案例；未经确认不会直接写入 Mnemosyne。
- 记忆 staging：`output/memory_staging/` 下待审阅的 JSONL，不是已生效的长期记忆。
- 记忆作用域：`global` 保存跨酒店安全规则，`hotel` 按 `hotel_key` 隔离单店经营经验。
